# Модел на заплахите и сигурност на UniCloud (Threat Model)

Този документ описва основните активи, входните точки и модела на заплахите по STRIDE методологията за проекта UniCloud, съобразено с използването на REST API с JSON.

---

## 1. Основни активи (Assets)
Системата защитава следните критични ресурси:
* **Потребителски акаунти и автентикация:** Данни за вход на студенти, преподаватели и администратори.
* **Учебни материали:** Качени файлове (PDF, презентации, видео линкове) и техните версии.
* **Потребителски статуси (Отметки):** Данни за това кой студент кои материали е маркирал като „прочетени“.
* **REST API endpoints:** Крайни точки за комуникация с JSON данни между Frontend-а и Backend-а.

---

## 2. Входни точки (Entry Points)
* **Автентикация / Login API:** Точка за вход на потребителите.
* **Интерфейс за качване на файлове (Upload API):** Използва се за добавяне на учебни материали.
* **Каталог и търсачка:** REST заявки за филтриране и преглед на курсове.
* **Административни функции:** Управление на правата и ролите в системата.

---

## 3. Модел на заплахите по STRIDE

| Категория по STRIDE | Описание на заплахата в контекста на UniCloud | Предвидена мярка за защита |
| :--- | :--- | :--- |
| **Spoofing** (Лъжене на самоличността) | Злоумишленик фалшифицира JSON Web Token (JWT) или се представя за друг потребител. | Използване на сигурна автентикация и валидация на токените на сървъра. |
| **Tampering** (Неоторизирана промяна на данни) | Студент се опитва да промени JSON заявка към API-то, за да редактира чужд материал. | Server-side проверка на правата (предотвратяване на IDOR/BOLA). |
| **Repudiation** (Опити за отричане на действия) | Потребител извършва чувствителна операция (напр. триење на материал), а после отрича. | Поддържане на сигурни системни логове на Backend ниво. |
| **Information Disclosure** (Изтичане на информация) | Студент получава достъп до скрити преподавателски материали през незащитени API маршрути. | Строга ролева система и забрана студент да управлява чужди ресурси. |
| **Denial of Service** (Укравяне на услугата) | Изпращане на огромни JSON заявки или прекалено големи файлове за качване. | Ограничаване на размера на файловете и rate limiting на критичните endpoints. |
| **Elevation of Privilege** (Повишаване на привилегиите) | Студент сменя ролята си в интерфейса, за да получи административни права. | Забрана да се разчита на frontend скриване; сървърът задължително проверява правата. |

---

## 4. Заключение
Този модел гарантира изпълнението на изискванията за сигурност на MVP версията на UniCloud.
