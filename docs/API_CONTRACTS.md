# API_CONTRACTS – UniCloud, Екип 2

**Статус:** предложение за Седмица 1 – чака потвърждение от PM-ите на Екипи 1, 3 и 4.
**Отговорници:** Радостин Павлов (PM), Златин Златинов (SE 1 – API), Стилиян Тодоричков (SE 3 – интеграции).
**Пълна спецификация:** OpenAPI (Swagger UI) на `/swagger-ui.html` – поддържа се от SE 1. Този документ описва договореностите; при разлика важи OpenAPI спецификацията, а този документ се обновява.

## 1. Общи правила

| Правило | Договорка |
| --- | --- |
| Адрес | `https://<домейн>/api/v1/...` |
| Версия | в пътя (`/v1`); несъвместима промяна → `/v2`, старата версия работи още поне 2 седмици |
| Формат | JSON, UTF-8; имената на полетата в camelCase |
| Дати и часове | ISO 8601 в UTC, напр. `2026-11-16T06:15:00Z` |
| Идентификатори | UUID като текст |
| Код на курс | общ за всички екипи: `<ДИСЦИПЛИНА>-<ГОДИНА><СЕМЕСТЪР>`, латиница, напр. `OIT-2026W` (W – зимен, S – летен) |
| Вход | `Authorization: Bearer <JWT>` (вж. раздел 3) |
| Страници | `?page=0&size=20` (най-много 100); отговорът съдържа `content`, `page`, `size`, `totalElements` |
| Кеш | публичните отговори имат `Cache-Control: public, max-age=60`; личните – `private, no-store` |
| Ограничение на заявките | при надвишаване – `429 Too Many Requests` с `Retry-After` |

### Формат на грешките

```json
{
  "status": 403,
  "error": "FORBIDDEN",
  "message": "Нямате права за тази операция.",
  "path": "/api/v1/courses/7f1c.../modules",
  "timestamp": "2026-11-16T06:15:02Z"
}
```

| Код | Кога |
| --- | --- |
| 400 | невалидни данни (с поле `fields` – списък с грешките по полета) |
| 401 | липсва или е невалиден токен |
| 403 | токенът е валиден, но ролята няма право |
| 404 | ресурсът не съществува **или** потребителят няма право да знае, че съществува |
| 409 | конфликт (напр. дублиран код на курс) |
| 413 | прекалено голям файл |
| 415 | непозволен тип файл |
| 429 | твърде много заявки |
| 5xx | грешка при нас – брои се срещу error budget |

## 2. Вътрешно API (за SE 2 – Frontend)

| Метод и път | Кой | Описание |
| --- | --- | --- |
| `GET /courses` | всички | каталог; филтри `discipline`, `teacher`, `semester` |
| `POST /courses` | преподавател, админ | нов курс |
| `GET /courses/{courseId}` | всички | курс с модули / седмици и занятия (една заявка за цялата структура) |
| `PUT /courses/{courseId}` · `DELETE /courses/{courseId}` | собственик, админ | промяна / изтриване |
| `POST /courses/{courseId}/modules` | собственик | нов модул / седмица |
| `POST /modules/{moduleId}/lessons` | собственик | ново занятие |
| `GET /lessons/{lessonId}/materials` | всички | материалите към занятие |
| `POST /lessons/{lessonId}/materials` | собственик | нов материал (`multipart/form-data` за файл или JSON за препратка) |
| `GET /materials/{materialId}` | всички | материал с текущата версия |
| `PATCH /materials/{materialId}` | собственик | описание, тагове, скриване |
| `POST /materials/{materialId}/versions` | собственик | нова версия на файла |
| `GET /materials/{materialId}/versions` | всички | история на версиите |
| `GET /materials/{materialId}/file?version=N` | всички | файлът (пренасочване към кеширан адрес) |
| `GET /search?q=&discipline=&teacher=&topic=&page=&size=` | всички | търсене (SE 1) |
| `PUT /materials/{materialId}/read` · `DELETE /materials/{materialId}/read` | студент | отметка „прочетено“ / премахване (SE 3) |
| `GET /courses/{courseId}/progress` | студент | собствените отметки за курса (SE 3) |
| `POST /auth/login` | всички | временен вход с демо акаунти (Седмица 1) |
| `GET /actuator/health` | Nginx, мониторинг | liveness / readiness (без `/api/v1`) |

### Материал (пример)

```json
{
  "id": "3b2e8c1a-...",
  "lessonId": "91d0...",
  "courseCode": "OIT-2026W",
  "type": "PRESENTATION",
  "title": "Лекция 1 – Въведение в облачните изчисления",
  "description": "Слайдове от първата лекция",
  "tags": ["облак", "въведение"],
  "currentVersion": 2,
  "fileUrl": "https://<домейн>/files/3b2e.../v2/lecture1.pdf",
  "videoUrl": null,
  "hidden": false,
  "updatedAt": "2026-11-15T18:20:00Z"
}
```

Типове материали: `NOTES` (конспект), `PRESENTATION`, `VIDEO_LINK`, `ASSIGNMENT` (условие на задача), `LITERATURE`.
Позволени файлове: PDF, PPTX, DOCX, PNG, JPG; до 50 MB (решение на Security – UC-13).

## 3. Екип 1 – Портал и идентичност (Екип 1 → Екип 2)

**Какво:** кой е потребителят, ролята му и в кои курсове е записан.
**Как:** JWT токен, издаден от портала на Екип 1, подписан с RS256; UniCloud проверява подписа с публичния ключ на Екип 1 (JWKS адрес).

```json
{
  "iss": "https://portal.<домейн>",
  "aud": "unicloud",
  "sub": "u-8f3a2c",
  "role": "STUDENT",
  "courses": ["OIT-2026W", "MATH-2026W"],
  "iat": 1795100000,
  "exp": 1795103600
}
```

| Поле | Договорка |
| --- | --- |
| `sub` | постоянен ID на потребителя, без имейл и ЕГН |
| `role` | `STUDENT`, `TEACHER` или `ADMIN` |
| `courses` | кодове на курсове във формата от раздел 1 |
| `exp` | токенът важи най-много 1 час |

**Седмица 1:** UniCloud издава временни токени със същите полета (демо акаунти), за да не се преправя кодът при свързването с Екип 1. Ограничаването по `courses` е за следваща седмица.

## 4. Екип 3 – Автоматично оценяване (Екип 2 → Екип 3)

**Какво:** условията на курсовите задачи (материали от тип `ASSIGNMENT`).
**Как:** REST, само четене; Екип 3 се идентифицира със собствен токен за услуга (`role: SERVICE`).

`GET /api/v1/integrations/assignments?courseCode=OIT-2026W`

```json
[
  {
    "materialId": "c41f...",
    "courseCode": "OIT-2026W",
    "title": "Курсова задача 1 – Docker",
    "version": 1,
    "fileUrl": "https://<домейн>/files/c41f.../v1/task1.pdf",
    "updatedAt": "2026-11-15T10:00:00Z"
  }
]
```

При нова версия на условието `version` се увеличава; Екип 3 решава дали старите решения остават към старата версия.

## 5. Екип 4 – Анализи и AI Ментор (Екип 2 → Екип 4)

### 5.1 Събития за прочетеното

**Как:** UniCloud изпраща `POST` към адрес на Екип 4 (webhook) при всяко събитие; при грешка – повторен опит до 3 пъти. Заявката е подписана: заглавка `X-UniCloud-Signature` = HMAC-SHA256 на тялото със споделена тайна.

```json
{
  "eventId": "e7a1...",
  "type": "material.read",
  "occurredAt": "2026-11-16T06:17:43Z",
  "userId": "p-5d9e1b",
  "courseCode": "OIT-2026W",
  "materialId": "3b2e8c1a-...",
  "version": 2
}
```

| Поле | Договорка |
| --- | --- |
| `type` | `material.viewed`, `material.read`, `material.unread`, `material.uploaded` |
| `userId` | **псевдоним** (HMAC от `sub`), не името, имейлът или `sub` – решение на Security (UC-14) |
| `eventId` | уникален; Екип 4 игнорира повторно получени събития |

**Седмица 1:** събитията се записват при нас в този формат; показва се поне едно примерно изпращане (реално или към фалшив адрес).

### 5.2 Текст на материалите за AI Ментор

`GET /api/v1/integrations/materials/{materialId}/text` → извлеченият текст от PDF / PPTX. **Само договорка** – реализация след Седмица 1.
